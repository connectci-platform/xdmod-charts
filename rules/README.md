# Payload content rules

Both producers (access-mcp in TypeScript, xdmod-mcp in Python) build a `ChartPayload` from XDMoD's answers by these rules. The schema says what shape is valid; these rules say what the values must be. Each rule names the fixture that pins it. Where it says "fixture: to come", the fixture is not written yet (Task 7 for weeks). Fixtures are compared as described in `fixtures/README.md`.

`rules/statistics.json` holds one entry per statistic either producer charts: `kind` (`total` or `average`), `unit` (a free string, so a new unit never hides a chart on an older client) and `additive` (true only when weeks may be summed, see rule 8).

1. Measure kind and what a missing period means. `measure.kind` is the statistic's `kind` in `rules/statistics.json`. For an id not listed, the fallback applies in both languages: an id starting `total_` or ending `_count` is a total, anything else is an average. `measureKind()` in this package is the reference. A total's missing period is `measure.missing: "zero"`: an empty period is 0. An average's is `"gap"`: an empty period is unknown, never 0, and stays `null`. `measure.unit` is the statistic's `unit`, omitted for an unlisted id. Fixture: aggregate-jobs-by-resource (total, zero); gap: average-leaves-gaps; unit: cpu-hours-by-resource-incomplete.

2. The period grid and `counted`. For a timeseries, `unit` is the requested unit when it is Day, Week, Month, Quarter or Year, else chosen from the range: under 6 whole months Day, under 120 months Month, otherwise Quarter. The grid is every period start from the period containing `start_date` through the one containing `end_date`. Every series has one point per grid start, in order, with `null` where XDMoD sent no value. A period XDMoD returns that is off the grid is an error. `counted` runs from the first period's start to the last period's end, so it can be wider than `requested`. For an aggregate there are no periods and `counted` equals `requested`. Fixture: aggregate-jobs-by-resource (aggregate); timeseries: timeseries-month-gaps, calendar-december-into-january, calendar-range-ends-at-month-end, partial-last-day (Day).

3. `data_through` and its precision. For a timeseries it is the start of the last period in which any series has a value, with `data_through_precision: "period"`. When the realm's latest data day is known, falls on or after that start and within the same period, it replaces the start and the precision is `"day"`. With Day units the precision is always `"day"`. With no value anywhere both are `null`. For an aggregate, `data_through` is the realm's latest data day, with precision `"day"`, only when that day is before the requested end; otherwise both are `null`. Fixture: aggregate-jobs-by-resource (null case); no-series-values (null for a timeseries); probe-day-inside-last-month, probe-day-after-range, probe-day-last-day-of-period, series-ended-before-probe-day; aggregate-incomplete-with-probe-day, aggregate-probe-reaches-end.

4. Early-ending series and `data_through_source`. Timeseries only. Run this decision sequence once per series, after rule 3. (a) If the chart's `data_through` is `null`, nothing runs. (b) `chartEnd` is the chart's `data_through` when its precision is `"day"`, else the end of the period that starts at `data_through`. (c) A series with no values is skipped. (d) Let `own` be the start of the series' last period with a value. (e) If the dimension is not `resource`, the series is marked only when `own` is before the start of the chart's last data period: `data_through = own`, precision `"period"` (`"day"` for Day units), source `"series"`; no zero fill. (f) If the dimension is `resource` and `resource_days` is null (the probe failed), the same marking applies with source always `"series"`; no zero fill. (g) If the dimension is `resource` and `resource_days` is non-null, and the resource has a day in `resource_days.days` with day >= `own`: for a total, every point after `own` is set to 0 up to the period containing min(day, `chartEnd`), whether or not a marker is set; then, only when day < `chartEnd`, `data_through = day`, precision `"day"`, source `"resource"`. An average is never filled. (h) Otherwise (resource, probe non-null, and the resource has no day or its day is before `own`): if `own` is not before the start of the chart's last data period, nothing is marked. Else `data_through = own`, precision `"period"` (`"day"` for Day units), and source is `"resource"` when the resource is absent from `days` and `own`'s period end is on or after the day before `resource_days.since` (a probe that covers the period end and found nothing means the resource has had no data since), otherwise `"series"`. An aggregate category gets `data_through = day` and source `"resource"` only when the dimension is `resource`, `resource_days` is non-null, the resource's day is before the chart's end (`data_through`, else the requested end) and not before the requested start. Fixture: early-end-fills-to-resource-last-day, early-end-fill-stops-at-last-day, early-end-day-inside-last-period, early-end-resource-retired, early-end-without-probe, early-end-probe-window-too-short, early-end-other-dimension-never-filled, early-end-daily-by-queue, early-end-average-other-dimension, early-end-average-by-resource-not-filled, early-end-several-resources, early-end-daily-series-stops, rank-prefixes-on-series, aggregate-marks-resources-that-stop.

5. Partial last period. `last_data_period_partial` is true when periods after the last one with data are empty, or when `data_through` has day precision and falls before the end of its period. Otherwise false. It is always false for an aggregate. `last_period_incomplete` is true when `counted.end` is on or after today (for an aggregate, when the requested end is). Fixture: aggregate-jobs-by-resource (false); partial-last-month, partial-last-day (true); timeseries-complete-last-period (incomplete false).

6. Ordered-bucket fill. A dimension is ordered when it is one of `jobsize`, `jobwalltime`, `jobwaittime`, `nodecount`, `gpu_count`. Categories of an ordered dimension are sorted into the dimension's bucket order (unknown names last, original order kept for ties). A bucket XDMoD left out is added with value 0 only when the statistic is a total, every bucket is known to have come back (`dimension_complete`), there is no paging (`has_more` false, `offset` 0), `dimension_filtered` is false (the request does not filter the group_by dimension itself), and at least one category came back. Otherwise nothing is added. Fixture: aggregate-fills-empty-buckets (fill); aggregate-no-fill-for-average, aggregate-no-fill-incomplete-buckets, aggregate-no-fill-when-more, aggregate-no-fill-with-offset, aggregate-no-fill-when-bucket-filtered (no fill); aggregate-ordered-bucket-order, aggregate-unknown-bucket-last, aggregate-nominal-not-reordered (order).

7. Ranking, `offset` and `others_count`. Names XDMoD numbers ("1. cluster-a") lose the rank prefix. `ranked_by` is `"value"`; XDMoD's order is kept, with `offset` the number of top-ranked entries skipped. `others_count` is the producer's count when XDMoD gave one; when it did not, it is `null` if `has_more` and 0 if not. No "Other" bucket is ever made. Fixture: aggregate-jobs-by-resource (no more); aggregate-has-more-others-count, aggregate-no-fill-when-more (null count), aggregate-offset-page (offset, rank prefixes), rank-prefixes-on-series.

8. Weeks. `unit: "Week"` is for additive statistics only (`additive: true`); a producer does not request weeks for any other. A week starts Monday. The fetch starts on the Monday on or before the start date and ends on the Sunday on or after the end date, capped at today. `counted` is those whole weeks. `last_period_incomplete` is set only when the today cap cut the last week. Fixture: to come (Task 7 weeks).

9. Warnings. A producer on this contract always emits `warnings`, an empty array when it has none; an absent `warnings` field means a pre-contract producer, and a client then applies its built-in warnings (`BUILT_IN_WARNINGS`). Each has a stable `code` and producer-worded `text`, and the order below is the order in the list. `waiting-not-counted` when the realm is Jobs and the last period is incomplete. `not-comparable-across-resources` when the dimension is `resource` and the statistic is `total_cpu_hours` or `avg_cpu_hours`. `mean-of-jobs` when the statistic starts with `avg_`. Fixture: aggregate-jobs-by-resource (none); cpu-hours-by-resource-incomplete, average-leaves-gaps, label-stripped-from-description (codes in order).

10. Measure description. `measure.description` is the label-stripped plain text of XDMoD's description. Convert in this order. (a) Replace matches of the regex `(?<![.!?:;,])\s*<br\s*\/?>\s*` (case-insensitive, global) with ". ". The lookbehind is checked at the start of the match, so the punctuation must be the immediately preceding character with no whitespace between: `"a.<br>b"` has no match here, so the next step turns it into "a. b", but `"a. <br>b"` matches (the match starts at the space) and gives "a. . b", a doubled period. A port must copy the regex, not paraphrase it. (b) Replace every remaining `<br\s*\/?>` (case-insensitive) with a single space. (c) Remove every other tag, regex `<[^>]*>`. (d) Decode exactly six entities, in this order: `&nbsp;` to a space, `&lt;`, `&gt;`, `&quot;`, `&#39;`, and last `&amp;`. (e) Collapse runs of whitespace to one space and trim. (f) If the label is non-empty and the result starts with `<label>:` (case-insensitive, `label` being `measure.label`), remove that prefix and trim; an empty label is never stripped. Fixture: aggregate-jobs-by-resource (the "Number of Jobs Ended:" prefix is stripped); label-stripped-from-description (HTML converted).

11. Adapter trimming. `BuilderInput.series` and `categories` are already trimmed: the producer's adapter, not the builder, does this. It drops gap-connector traces (name containing "gap connector", any case), "All N Others" entries (recording N), and, for a timeseries only, series with no values; applies `request.limit` (XDMoD is asked for one more than the limit, so a surplus means more); and derives `has_more` (something was cut or XDMoD reported others) and `others_count` (cut count plus N, `null` when more exist but XDMoD gave no N, 0 when nothing is left out), as access-mcp's `trimToLimit` does. `request.limit` is informational to the builder. No builder fixture: fixtures hold post-trim input, so each producer tests its own adapter (access-mcp: chart-input.test.ts and the trimToLimit cases in its server tests).

12. Optional context fields. `time_basis: { zone }` is set only when the builder is given a time zone. `instance: { name, url }` is set only when the builder is given an instance, and a producer emits it only with an https url. `link` is the given link or `null`. `filters.notes` is the request's notes. `retrieved` is today. Fixture: aggregate-jobs-by-resource (all unset or null); timeseries-month-gaps (time_basis and instance set).
