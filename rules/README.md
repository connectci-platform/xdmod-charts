# Payload content rules

Both producers (access-mcp in TypeScript, xdmod-mcp in Python) build a `ChartPayload` from XDMoD's answers by these rules. The schema says what shape is valid; these rules say what the values must be. Each rule names the fixture that pins it. Where it says "fixture: to come", the fixture is not written yet (Task 5 export from access-mcp, Task 7 for weeks and the Python producer). Fixtures are compared as described in `fixtures/README.md`.

`rules/statistics.json` holds one entry per statistic either producer charts: `kind` (`total` or `average`), `unit` (a free string, so a new unit never hides a chart on an older client) and `additive` (true only when weeks may be summed, see rule 8).

1. Measure kind and what a missing period means. `measure.kind` is the statistic's `kind` in `rules/statistics.json`. For an id not listed, the fallback applies in both languages: an id starting `total_` or ending `_count` is a total, anything else is an average. `measureKind()` in this package is the reference. A total's missing period is `measure.missing: "zero"`: an empty period is 0. An average's is `"gap"`: an empty period is unknown, never 0, and stays `null`. `measure.unit` is the statistic's `unit`, omitted for an unlisted id. Fixture: aggregate-jobs-by-resource (total, zero); gap case to come (Task 5 export).

2. The period grid and `counted`. For a timeseries, `unit` is the requested unit when it is Day, Week, Month, Quarter or Year, else chosen from the range: under 6 whole months Day, under 120 months Month, otherwise Quarter. The grid is every period start from the period containing `start_date` through the one containing `end_date`. Every series has one point per grid start, in order, with `null` where XDMoD sent no value. A period XDMoD returns that is off the grid is an error. `counted` runs from the first period's start to the last period's end, so it can be wider than `requested`. For an aggregate there are no periods and `counted` equals `requested`. Fixture: aggregate-jobs-by-resource (aggregate); timeseries: to come (Task 5 export).

3. `data_through` and its precision. For a timeseries it is the start of the last period in which any series has a value, with `data_through_precision: "period"`. When the realm's latest data day is known, falls on or after that start and within the same period, it replaces the start and the precision is `"day"`. With Day units the precision is always `"day"`. With no value anywhere both are `null`. For an aggregate, `data_through` is the realm's latest data day, with precision `"day"`, only when that day is before the requested end; otherwise both are `null`. Fixture: aggregate-jobs-by-resource (null case); others to come (Task 5 export).

4. Early-ending series and `data_through_source`. A series or category that stops before the chart's data end carries its own `data_through`. When the dimension is `resource` and per-resource days are known, a resource's trailing empty periods are filled with 0 (totals only) up to its last day, and `data_through_source` is `"resource"`. A resource absent from a probe that covers the end of its last period is `"resource"`; otherwise, and for every non-resource dimension, it is `"series"` and the gaps stay. An average's empty periods stay gaps. An aggregate category gets `data_through` and source `"resource"` only for a resource whose last day is before the chart's end and not before the start. Fixture: to come (Task 5 export).

5. Partial last period. `last_data_period_partial` is true when periods after the last one with data are empty, or when `data_through` has day precision and falls before the end of its period. Otherwise false. It is always false for an aggregate. `last_period_incomplete` is true when `counted.end` is on or after today (for an aggregate, when the requested end is). Fixture: aggregate-jobs-by-resource (false); others to come (Task 5 export).

6. Ordered-bucket fill. A dimension is ordered when it is one of `jobsize`, `jobwalltime`, `jobwaittime`, `nodecount`, `gpu_count`. Categories of an ordered dimension are sorted into the dimension's bucket order (unknown names last, original order kept for ties). A bucket XDMoD left out is added with value 0 only when the statistic is a total, every bucket is known to have come back (`dimension_complete`), there is no paging (`has_more` false, `offset` 0), the dimension is not filtered, and at least one category came back. Otherwise nothing is added. Fixture: to come (Task 5 export).

7. Ranking, `offset` and `others_count`. Names XDMoD numbers ("1. cluster-a") lose the rank prefix. `ranked_by` is `"value"`; XDMoD's order is kept, with `offset` the number of top-ranked entries skipped. `others_count` is the producer's count when XDMoD gave one; when it did not, it is `null` if `has_more` and 0 if not. No "Other" bucket is ever made. Fixture: aggregate-jobs-by-resource (no more); has_more case to come (Task 5 export).

8. Weeks. `unit: "Week"` is for additive statistics only (`additive: true`); a producer does not request weeks for any other. A week starts Monday. The fetch starts on the Monday on or before the start date and ends on the Sunday on or after the end date, capped at today. `counted` is those whole weeks. `last_period_incomplete` is set only when the today cap cut the last week. Fixture: to come (Task 7 weeks).

9. Warnings. `warnings` is omitted when there are none; each has a stable `code` and producer-worded `text`, and the order below is the order in the list. `waiting-not-counted` when the realm is Jobs and the last period is incomplete. `not-comparable-across-resources` when the dimension is `resource` and the statistic is `total_cpu_hours` or `avg_cpu_hours`. `mean-of-jobs` when the statistic starts with `avg_`. Fixture: aggregate-jobs-by-resource (none); others to come (Task 5 export).

10. Optional context fields. `time_basis: { zone }` is set only when the builder is given a time zone. `instance: { name, url }` is set only when the builder is given an instance. `link` is the given link or `null`. `filters.notes` is the request's notes. `retrieved` is today. Fixture: aggregate-jobs-by-resource (all unset or null).
